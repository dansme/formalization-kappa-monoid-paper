# Comparator challenge

A self-contained statement of the paper's main results, checkable with
[comparator](https://github.com/leanprover/comparator).

| File | Role | Trusted? |
|---|---|---|
| `Challenge.lean` | the definitions and the theorems, from Mathlib alone, proofs `sorry` | **read this** |
| `config.json` | the theorems to check and the permitted axioms | read this |
| `Defs.lean` | `Challenge.lean` without its theorems, generated by `scripts/comparator_defs.py` | no |
| `Bridge/` | the challenge's definitions agree with the library's | no |
| `Solution.lean` | the challenge's theorems with proofs, generated by `scripts/comparator_solution.py` | no |

The comparator checks that every declaration the challenge's theorems mention is the same in the
solution's environment, that the solution proves exactly those statements, and that the proofs
use only `propext`, `Quot.sound` and `Classical.choice`.  So `Challenge.lean` and `config.json` are
all a reader has to check, besides Mathlib.

Covered: Theorem 3.12, Theorem 4.3, Corollary 4.5 and Theorem 5.3.  The rest of the paper is formalised in
`KappaMonoid/` and indexed in `KappaMonoid/Paper/`.

## Regenerating

After editing `Challenge.lean`, or a proof in `scripts/comparator_solution.py`:

```sh
python3 scripts/comparator_defs.py && python3 scripts/comparator_solution.py
lake build Comparator        # the only `sorry`s are the challenge's
```

CI runs both scripts with `--check` and builds the library.

## Running the comparator

The comparator and `lean4export` must match this project's Lean version (v4.33.0): comparator at
commit `c0c5a52` (the last one on v4.33.0), `lean4export` at tag `v4.33.0` (which that commit pins).

```sh
git clone https://github.com/leanprover/comparator && cd comparator && git checkout c0c5a52
lake build lean4export comparator
cd /path/to/kappa_formalized
COMPARATOR_LEAN4EXPORT=/path/to/comparator/.lake/packages/lean4export/.lake/build/bin/lean4export \
  lake env /path/to/comparator/.lake/build/bin/comparator Comparator/config.json
```

That runs the builds in a `landrun` sandbox, which must be on `PATH`.  Without it, set
`COMPARATOR_LANDRUN=/path/to/comparator/scripts/fake-landrun.sh`.  That skips the sandbox, which is
fine for checking your own solution, not an untrusted one.
